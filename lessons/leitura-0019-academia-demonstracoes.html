Antes da aula — Teoria

Conceito

Uma demonstração explica um requisito por uma ação executada, seu resultado e seu limite. A amostra de academia ajuda a comparar responsabilidades, sem exigir outro sistema completo. Backup é uma cópia preparada para recuperação; sua utilidade precisa ser conferida. Em SQLite, a API backup copia por conexões. Use origem fictícia, destino novo e consulta conhecida na cópia, preservando o original. A versão demonstrada precisa corresponder aos arquivos e registros entregues.

Exemplo mínimo comentado

Consultar uma cópia por outra conexão

import sqlite3

origem = sqlite3.connect(":memory:")
copia = sqlite3.connect(":memory:")
origem.execute("CREATE TABLE marcas (id INTEGER, nome TEXT)")
origem.execute("INSERT INTO marcas VALUES (?, ?)", (22, "Lilás"))
origem.commit()
# Copie pela conexão e confira um dado conhecido no destino.
origem.backup(copia)
print(copia.execute("SELECT id, nome FROM marcas").fetchone())
print("Origem:", origem.execute("SELECT count(*) FROM marcas").fetchone()[0])
origem.close()
copia.close()
# O desafio usa caminhos de arquivos e um destino novo.

O ensaio usa duas bases em memória e não substitui o teste de caminhos. Na atividade, confira origem ausente, destino existente, integridade e registros conhecidos na cópia, sem restaurar sobre o banco principal.

Resultado esperado do ensaio
(22, 'Lilás')
Origem: 1

Três erros comuns

  1. Apresentar telas sem relacionar ação, requisito e evidência.
  2. Considerar um backup válido só porque um arquivo foi criado.
  3. Sobrescrever origem/destino existente ou exigir reimplementação integral da academia.

Leve a ideia para a interface e para o projeto ↗

1. Problema concreto

Uma cópia de banco existe em outra pasta. Como conferir se ela realmente pode ser usada sem arriscar o original?

2. Entenda a ideia

Backup é uma cópia preparada para recuperação. Para demonstrar utilidade, você precisa abrir a cópia em outro caminho e conferir registros conhecidos.

SQLite possui uma API backup para copiar o banco por uma conexão. Isso evita tratar o arquivo principal isoladamente enquanto pode haver alterações relacionadas em andamento.

Escolha um destino novo, mantenha a origem e faça o ensaio de restauração fora do banco principal. Neste exercício, use somente dados fictícios.

Na entrega, inclua código, README e recursos autorizados. Ambientes, caches, credenciais e dados operacionais não são necessários para reproduzir a aplicação.

Para conferir o uso da interface, localize o foco atual e percorra os controles com Tab; use Shift+Tab para voltar. Com foco no botão, teste seu acionamento pelo teclado. Observe interface da candidata demonstrada com rótulos/mensagens/teclado; backup e análise não exigem uma GUI nova. Depois de uma recusa, corrija a entrada na mesma sessão e descreva o que permaneceu.

Backup não é apenas uma cópia que existe; é uma cópia que pode ser conferida em outro caminho. Para SQLite, use a API backup de uma conexão, evitando copiar isoladamente um arquivo enquanto pode haver gravação em andamento.
