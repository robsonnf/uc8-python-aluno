A05 — Sistema escolar: grupos e janelas de consulta

Organizar o formulário em grupos e abrir consultas que preservam o retrato do último registro confirmado.

Use os mesmos dados fictícios e regras da A04. As consultas são retratos da abertura; o registro não é gravado permanentemente. A imagem é opcional e o cabeçalho funciona em texto.

Antes da aula — Teoria

Conceito

Um contêiner organiza outros controles: o pai de cada widget é escolhido quando ele é criado. Cada grupo tem sua própria grade; sticky ocupa espaço disponível e o peso das linhas/colunas permite crescer. Uma consulta Toplevel pertence à aplicação existente e pode apresentar um retrato do confirmado. Esse retrato mantém os dados da abertura, mesmo quando a principal recebe outra confirmação. Fechar a consulta deve preservar a principal.

Exemplo mínimo comentado

Planejar grupos e conservar um retrato

grupos = {"Identificação": ["código"], "Medidas": ["valor"]}
# O mapa planeja os pais; ainda não cria widgets.
for pai, campos in grupos.items():
    print(pai, "->", ", ".join(campos))

confirmado = {"nome": "Nina", "valor": 2}
retrato = confirmado.copy()  # Valores simples neste ensaio.
confirmado["nome"] = "Ivo"
print("Consulta:", retrato["nome"])
print("Principal:", confirmado["nome"])

# Na GUI, cada consulta recebe o retrato da sua abertura.

O mapa e os dicionários representam uma decisão de organização. Na prática, crie Frame/LabelFrame com pais explícitos e Toplevel na única aplicação. Copiar o mapa não move widgets já criados.

Resultado esperado do ensaio
Identificação -> código
Medidas -> valor
Consulta: Nina
Principal: Ivo

Três erros comuns

  1. Desenhar um grupo sem criar os campos com esse grupo como pai.
  2. Configurar expansão apenas na principal e esquecer os contêineres internos.
  3. Usar os dados em edição como consulta ou fechar a principal ao fechar uma consulta.

Contêineres e hierarquia ↗

1. Problema concreto

O formulário cresceu e os campos ficaram difíceis de localizar. Como agrupá-los sem mudar as regras do cálculo?

2. Entenda a ideia

Frame funciona como uma caixa organizadora. LabelFrame é uma caixa com título, como Identificação ou Notas. Os campos colocados nela são seus filhos.

O primeiro argumento ao criar um widget informa seu pai. Para mover um campo para um grupo, você precisa criá-lo com esse grupo como pai; só desenhar a caixa não o transfere.

Cada pai tem sua própria grade. A linha zero de Notas e a linha zero de Identificação não são a mesma posição. Primeiro organize os grupos; depois os campos dentro deles.

sticky="ew" pede ao campo que ocupe a largura disponível. O weight da coluna do pai permite que essa largura cresça ao redimensionar.

3. Exemplo comentado

Planejar grupos antes de criar os widgets
# Um mapa em texto ajuda a planejar antes de construir a janela.
grupos = {"Identificação": ["Nome", "Turma"], "Notas": ["Nota 1", "Nota 2"]}
print("Identificação:", grupos["Identificação"])
print("Notas:", grupos["Notas"])

Regras e detalhes para consultar durante o desafio

Arquitetura: uma Tk contém um Frame base; ele contém os grupos Identificação, Notas e Ações. Cada grupo é pai dos seus próprios widgets. Os callbacks continuam chamando as funções de validação da A04; a mudança visual não muda a regra das notas.

Frame é um contêiner para organizar widgets; LabelFrame acrescenta uma borda com título do grupo. O primeiro argumento de cada widget define seu pai. Criar um grupo na tela não muda automaticamente o pai das Entry já existentes: elas precisam ser criadas no contêiner correto.

grid organiza os filhos de um pai. row=0 dentro de Identificação e row=0 dentro de Notas são posições em grades diferentes. Defina onde o grupo fica na base e, separadamente, onde cada campo fica dentro do grupo.

sticky="ew" permite ocupar a largura disponível, mas a coluna também precisa receber weight para crescer. Configure a coluna do pai que você quer expandir; ampliar só a janela principal não faz todas as colunas internas crescerem.

Use grid para os filhos de cada contêiner nesta atividade. Preserve a ordem nome → turma → cinco notas → ações, rótulos claros e mensagens em texto. Não acrescente dados pessoais reais nem novas regras de média.

Consultas como retratos ↗

1. Problema concreto

Você abriu uma consulta de Lia e depois confirmou os dados de Rui. A consulta antiga deve mudar sozinha?

2. Entenda a ideia

Nesta prática, cada consulta é uma fotografia dos dados no momento da abertura. O nome técnico usado às vezes é snapshot; aqui vamos chamá-la de retrato.

Uma Toplevel cria a janela de consulta dentro da aplicação existente. A principal continua sendo a única Tk, com um único mainloop.

Monte o texto do confirmado uma vez, antes de mostrar a consulta. Fechar essa Toplevel deve fechar só a consulta; a janela principal continua disponível.

Para conferir o uso da interface, localize o foco atual e percorra os controles com Tab; use Shift+Tab para voltar. Com foco no botão, teste seu acionamento pelo teclado. Observe títulos dos grupos, identificação das consultas, foco, redimensionamento e funcionamento textual sem imagem. Depois de uma recusa, corrija a entrada na mesma sessão e descreva o que permaneceu.

3. Exemplo comentado

Criar um retrato que não muda sozinho
confirmado = {"nome": "Lia", "media": 8.0}
retrato = f"{confirmado['nome']}: {confirmado['media']:.1f}"
confirmado["nome"] = "Rui"  # O texto já criado não é recalculado sozinho.
print(retrato)
print(confirmado["nome"])

Exemplo: uma janela auxiliar e o seu fechamento
import tkinter as tk
from tkinter import ttk

principal = tk.Tk()
principal.title("Janela principal")

def abrir_ajuda():
    ajuda = tk.Toplevel(principal)
    ajuda.title("Ajuda local")
    ttk.Label(ajuda, text="A principal continua aberta.").grid(padx=12, pady=12)
    def fechar(event=None):
        ajuda.destroy()
        principal.focus_set()
    ttk.Button(ajuda, text="Fechar ajuda", command=fechar).grid(pady=12)
    ajuda.protocol("WM_DELETE_WINDOW", fechar)
    ajuda.bind("<Escape>", fechar)

ttk.Button(principal, text="Abrir ajuda", command=abrir_ajuda).grid(padx=12, pady=12)
principal.mainloop()

Localize quem é destruído em cada fechamento. A consulta escolar também precisa decidir de qual registro vem o conteúdo.

Regras e detalhes para consultar durante o desafio

Mantenha a principal aberta e acrescente Consultar. Use tk.Toplevel(principal) para criar uma janela de consulta ligada à aplicação existente. Há uma única Tk e um único mainloop; não coloque outro mainloop na consulta.

Antes do primeiro registro válido, Consultar deve orientar a calcular, sem abrir janela vazia. Depois, obtenha o texto do registro confirmado no instante da abertura e mostre-o em rótulos de leitura. Não busque os textos editáveis para montar a consulta.

Cada acionamento de Consultar pode abrir um novo retrato independente. C1 conserva os dados da sua abertura; editar ou confirmar outro registro na principal não muda C1. Uma nova C2 mostra o conjunto confirmado mais recente. Identifique essa regra na própria consulta.

A consulta fica sem bloqueio da principal, para permitir testar essa sequência. Botão Fechar consulta, X e Escape devem destruir somente a Toplevel. O callback ligado a bind recebe um evento; uma função com event=None pode atender também ao botão e ao fechamento da janela.

Para uma imagem opcional, monte o caminho com Path(__file__).resolve().parent / "marca-a05.png". Isso procura ao lado do script, mesmo quando o terminal estiver em outra pasta. Crie PhotoImage com esse arquivo e conserve a referência, por exemplo em um atributo do rótulo.

A aula não distribui PNG nem logotipo. Se optar por usar uma imagem, crie um PNG próprio autorizado e coloque-o ao lado do script. Ausência ou erro de leitura mantém o texto Sistema escolar fictício; o programa deve funcionar sem imagem. Canvas e rolagem ficam como aprofundamento.
