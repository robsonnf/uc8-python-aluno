Antes da aula — Teoria

Conceito

Um arquivo guarda texto em um caminho. Ao gravar, escolhemos o texto e sua codificação; ao ler, recuperamos esse texto. JSON transforma dados em texto estruturado e permite fazer o caminho de volta. Depois da leitura, ainda é preciso conferir os dados e suas regras. Uma falha não deve sobrescrever o original nem apagar a tentativa. Trocar abas do Notebook muda a apresentação, preservando o pedido já criado.

Exemplo mínimo comentado

Gravar e ler JSON em uma pasta temporária

import json
from pathlib import Path
from tempfile import TemporaryDirectory

# A pasta de ensaio será removida ao terminar este bloco.
with TemporaryDirectory() as pasta:
    caminho = Path(pasta) / "cores.json"
    texto = json.dumps([{"id": 4, "nome": "Lilás"}], ensure_ascii=False)
    caminho.write_text(texto, encoding="utf-8")
    lido = caminho.read_text(encoding="utf-8")
    dados = json.loads(lido)  # Texto volta a ser dados.
    print(dados[0]["id"], dados[0]["nome"])
print("Ensaio encerrado")

O exemplo cria somente sua pasta temporária, sem usar o catálogo do projeto. write_text grava texto; read_text recupera texto; loads decodifica JSON. O desafio acrescenta validação do catálogo, escrita temporária/substituição e preservação em falhas.

Resultado esperado do ensaio
4 Lilás
Ensaio encerrado

Três erros comuns

  1. Confundir texto JSON decodificado com dados já validados.
  2. Apagar um arquivo inválido ou substituí-lo por vazio automaticamente.
  3. Recriar o pedido ao navegar ou anunciar sucesso ao cancelar o seletor.

1. Problema concreto

O catálogo foi salvo em um arquivo, mas alguém apagou uma vírgula dele. Como avisar o problema sem substituir os dados por uma lista vazia?

2. Entenda a ideia

Antes de tratar o catálogo, separe três operações do ensaio: Path identifica o caminho, write_text/read_text gravam e leem texto com UTF-8, e json.dumps/loads convertem entre texto e dados. A pasta temporária serve somente ao ensaio; o catálogo da atividade usa o caminho escolhido e precisa ser preservado na falha.

JSON é uma forma de escrever dados em texto. Uma lista de produtos pode conter objetos com id, nome e preco_centavos; os métodos das classes não são gravados nesse texto.

Decodificar é transformar texto JSON em dados Python. Depois disso, confira a estrutura e as regras: ser um JSON válido não garante que todos os produtos têm códigos únicos e preços permitidos.

Arquivo ausente e arquivo com erro são situações diferentes. Um arquivo inválido deve ficar disponível para correção; não o sobrescreva automaticamente.

Ao salvar, confira os dados antes. Escreva uma versão temporária no mesmo diretório e só substitua o destino quando terminar. Assim, uma escrita interrompida não deve destruir o arquivo anterior.

Regras e detalhes para consultar durante o desafio

Conserve o pedido e acrescente arquivos.py para ler, validar e salvar uma lista JSON. main.py organiza Pedido e Exercício JSON em abas e menu. O exercício de arquivo é separado do pedido; carregar JSON não altera silenciosamente o carrinho.

JSON representa dados, não objetos vivos com seus métodos. Um catálogo será uma lista de objetos com id, nome e preco_centavos; preço é inteiro em centavos, evitando misturar strings com moeda e números aproximados no arquivo.

Arquivo ausente e arquivo inválido são situações diferentes. Ausente pode representar catálogo ainda não criado; inválido precisa de uma mensagem e preservação dos bytes originais, sem substituí-lo automaticamente por uma lista vazia.

Depois de decodificar, valide a estrutura: lista, chaves previstas, IDs inteiros positivos únicos, nome com texto e preço inteiro positivo. Um JSON sintaticamente válido ainda pode violar o contrato do catálogo.

Para gravar, valide primeiro, escreva UTF-8 em um temporário no mesmo diretório e substitua o destino somente após completar a escrita. Erro de permissão/caminho deve ser comunicado; o programa não deve anunciar sucesso se o arquivo não foi salvo.
