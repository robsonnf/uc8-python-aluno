Antes da aula — Teoria

Conceito

Persistência é conservar os dados depois de encerrar e abrir a aplicação. SQLite guarda registros em um banco; o repositório concentra as operações de gravação e consulta. Parâmetros separam os valores do comando SQL. A confirmação da gravação precisa acontecer antes de anunciar sucesso. JSON representa dados estruturados em texto; CSV apresenta linhas e colunas para intercâmbio; SQLite permite operações e consultas no banco. Nesta aula, o pedido ainda permanece em memória.

Exemplo mínimo comentado

Separar comando SQL e valor recebido

import sqlite3

con = sqlite3.connect(":memory:")  # Banco só para este ensaio.
con.execute("CREATE TABLE marcas (id INTEGER PRIMARY KEY, nome TEXT)")
nome = "D'água"
# O valor é passado separado do comando, sem concatenação.
con.execute("INSERT INTO marcas (nome) VALUES (?)", (nome,))
con.commit()
linha = con.execute("SELECT id, nome FROM marcas").fetchone()
print(linha[0], linha[1])
con.close()
# No desafio, reabra o MESMO caminho de banco em arquivo.

Este banco em memória existe somente enquanto a conexão está aberta. A atividade usa um arquivo de banco e exige reabertura para comprovar persistência; não atribua esse comportamento ao ensaio em memória.

Resultado esperado do ensaio
1 D'água

Três erros comuns

  1. Concatenar o valor digitado dentro do comando SQL.
  2. Anunciar sucesso antes de confirmar a gravação ou depois de uma falha.
  3. Reabrir outro caminho e concluir que o registro desapareceu.

Entenda a ideia e faça um ensaio ↗

1. Problema concreto

Você cadastrou um produto, fechou o programa e perdeu o cadastro. Onde guardar os dados para encontrá-los ao abrir novamente?

2. Entenda a ideia

Até aqui, muitos dados existiam apenas na memória do programa. SQLite permite guardar registros em um arquivo de banco. Persistência é essa capacidade de conservar os dados depois de encerrar a aplicação.

Uma tabela organiza registros em linhas e informações em colunas. Produtos terão id, nome e preco_centavos. A chave primária id identifica a linha mesmo que o nome mude.

SQL é a linguagem usada para pedir operações ao banco. Comece separando CREATE TABLE, que prepara a estrutura, de INSERT, que inclui uma linha, e SELECT, que consulta.

O primeiro ensaio usa :memory:, um banco que existe só enquanto a conexão está aberta. Para comprovar persistência na atividade, você precisará usar um arquivo fictício, fechar e reabrir o mesmo caminho.

3. Exemplo comentado

Criar, incluir e consultar em um banco de ensaio
import sqlite3

con = sqlite3.connect(":memory:")  # Ensaio sem criar arquivo no computador.
con.execute("CREATE TABLE cores (id INTEGER PRIMARY KEY, nome TEXT)")
con.execute("INSERT INTO cores VALUES (?, ?)", (1, "azul"))  # Dados nos parâmetros.
con.commit()  # Confirme a gravação desta transação.
linha = con.execute("SELECT nome FROM cores WHERE id=?", (1,)).fetchone()
print(linha[0])  # fetchone devolveu uma linha; posição zero é a coluna nome.
con.close()     # Feche o recurso que abriu.

Execute este ensaio separadamente, em ensaio.py. Leia os comentários e preveja a saída antes de executar. Depois faça as mudanças guiadas abaixo; o ensaio não completa os arquivos do desafio.

Regras e detalhes para consultar durante o desafio

repositorio.py abre conexões, cria tabelas e executa SQL parametrizado. main.py coleta nome/preço e atualiza a Treeview após a gravação. pagamento.py fornece a interpretação monetária; o banco armazena preco_centavos inteiro.

Uma tabela reúne registros com colunas definidas. A chave primária id identifica cada produto; nome é apresentação e pode se repetir. Não presuma SQL anterior: desenhe duas linhas de produtos e identifique quais valores pertencem a cada coluna.

Conecte a um arquivo fictício escolhido para o projeto e crie a tabela com IF NOT EXISTS. Isso não deve apagar dados existentes. Mantenha o caminho explícito: caminhos relativos à pasta do terminal podem fazer parecer que os dados desapareceram quando, na verdade, outro arquivo foi aberto.

Use INSERT com placeholders ? e uma tupla de valores. Texto como Picolé d'água é dado, não parte da sintaxe SQL. Não monte SQL concatenando nomes ou preços digitados; valide o requisito e deixe a biblioteca associar os parâmetros.

Uma operação de gravação deve confirmar a transação ou desfazê-la em caso de erro. with con trata commit/rollback, mas não fecha a conexão sozinho; combine-o com closing ou fechamento explícito. A importação do módulo não deve criar banco nem abrir janela.

Retome os três usos do projeto: JSON representa o catálogo em texto estruturado; CSV intercambia o relatório em linhas/colunas; SQLite guarda registros e permite operações/consultas. Um formato não substitui automaticamente o outro. Nesta etapa, persistem produtos; a montagem do pedido continua em memória.

Leve a ideia para a interface e para o projeto ↗

1. Problema concreto

O botão Salvar limpou os campos, mas a gravação falhou. Como preservar a informação para a pessoa tentar novamente?

2. Entenda a ideia

Repositório é o módulo que conversa com o banco. A janela lê os campos, pede a gravação a esse módulo e espera seu resultado.

A ordem importa: conferir preço e nome → gravar → consultar a lista atualizada → mostrar sucesso. Limpar ou anunciar sucesso antes da gravação pode esconder uma falha.

Transação é um grupo de alterações que será confirmado por commit ou desfeito por rollback. Na implementação, with con ajuda a controlar essa decisão, mas não fecha a conexão sozinho; faça também o fechamento.

Nesta aula, os produtos persistem e o pedido ainda usa a montagem anterior. A integração do catálogo do banco acontecerá na A17, de forma explícita.

Para conferir o uso da interface, localize o foco atual e percorra os controles com Tab; use Shift+Tab para voltar. Com foco no botão, teste seu acionamento pelo teclado. Observe campos de produto/listagem, mensagem de salvo só após sucesso, identificação do banco e teclado. Depois de uma recusa, corrija a entrada na mesma sessão e descreva o que permaneceu.
