Antes da aula — Teoria

Conceito

Uma classe descreve dados e ações; cada chamada cria uma instância. __init__ prepara os dados e self identifica o objeto que recebeu um método. Uma coleção criada para cada instância evita misturar registros independentes. Um módulo é um arquivo Python que outro pode importar. O modelo recebe valores comuns e pode ser testado sem janela; a interface lê campos e mostra respostas usando o mesmo modelo.

Exemplo mínimo comentado

Dois marcadores com históricos próprios

class Marcador:
    def __init__(self):
        self.valores = []  # Uma coleção por objeto.

    def adicionar(self, valor):
        self.valores.append(valor)  # Atua sobre self.

primeiro = Marcador()
segundo = Marcador()
primeiro.adicionar(3)
primeiro.adicionar(5)
print("Primeiro:", sum(primeiro.valores))
print("Segundo:", sum(segundo.valores))

Execute em um ensaio separado. A atividade usa Aluno e suas validações; o exemplo mostra apenas inicialização e independência. O modelo da atividade permanece sem imports de widgets.

Classe, instância e responsabilidade ↗

1. Problema concreto

Se o programa guardar dois alunos, como garantir que mudar as notas de um não altere as do outro?

2. Entenda a ideia

Uma classe descreve os dados e as ações de um tipo de objeto. Cada chamada Aluno() cria uma instância: um aluno específico, com seus próprios dados.

O método __init__ prepara o objeto novo. self identifica o objeto que recebeu a chamada. Em lia.atualizar(...), self é lia; em rui.atualizar(...), é rui.

Crie a lista de notas dentro de __init__, em self.notas, para que cada aluno receba uma lista nova. rui = lia não cria outro aluno: cria outro nome para o mesmo objeto.

aluno.py conterá as regras; verificar_modelo.py poderá usá-las sem janela. main.py usará esse mesmo modelo para responder aos cliques. Um modelo é a parte que guarda e confere os dados do aplicativo.

Regras e detalhes para consultar durante o desafio

Arquitetura antes do código: aluno.py terá a classe Aluno e suas regras; verificar_modelo.py importará Aluno e fará verificações em texto; main.py importará Aluno e criará os widgets. aluno.py não importa main nem Tkinter. Desenhe duas setas apontando para aluno.py.

Uma classe descreve os dados e comportamentos de seus objetos. Aluno() cria uma nova instância e chama __init__ para inicializá-la. Cada aluno começa com nome e turma vazios e uma lista de notas vazia; ainda não há registro confirmado.

Um atributo de instância guarda dado daquele objeto, como self.nome. Um método é uma função definida na classe; em lia.atualizar(...), self recebe automaticamente o objeto lia. self é o nome convencional desse primeiro parâmetro; a chamada não repete lia como argumento.

Crie a lista em self.notas dentro de __init__. Uma lista definida diretamente no corpo da classe pode ser compartilhada por instâncias. Duas chamadas Aluno() criam dois objetos; rui = lia apenas dá outro nome ao mesmo objeto.

Contrato do modelo: atualizar(nome, turma, notas_texto) recebe dois textos e uma lista com cinco textos, devolve uma mensagem e confirma nome/turma/notas só depois de validar tudo. Adapte suas regras da A05, montando uma lista numérica nova antes de escrever nos atributos.

calcular_media() retorna None antes do primeiro válido e um número depois. Cinco notas zero dão 0.0: isso é um registro válido. Use is None para distinguir os casos. resumo() usa apenas os atributos confirmados e formata a média com uma casa; não guarde uma segunda média que possa ficar desatualizada.

Os atributos são acessíveis em Python; nesta arquitetura a interface consulta o objeto por métodos e confirma pelo método atualizar. Escrever aluno.notas diretamente na interface quebraria o caminho de validação combinado.

Use assert condição para tornar uma previsão verificável: se a condição for falsa, Python interrompe com AssertionError e mostra a linha. Execute sem -O, que desativa asserts. Assert serve aqui à verificação; a validação dos dados do usuário continua com if e mensagens, como na A05.

Os iniciais ainda têm TODOs. As funções de verificação retornam False até serem completadas; troque para True somente depois de implementar os asserts. Uma mensagem de conclusão não substitui conferir o que foi efetivamente testado.

Exemplo: uma previsão que pode falhar
valores = [2, 4, 6]
assert len(valores) == 3
assert sum(valores) == 12
print("As duas previsões conferem.")

Altere a previsão da soma, execute novamente e leia a linha da falha. Use esse recurso para comparar o comportamento dos seus objetos.

Ligue os módulos à interface ↗

1. Problema concreto

A interface passou a usar uma classe. Como evitar criar um aluno novo a cada clique e perder o registro anterior?

2. Entenda a ideia

Crie uma instância antes de definir ou usar os callbacks. Os cliques seguintes devem chamar os métodos desse mesmo objeto.

Um módulo é um arquivo Python que pode ser importado por outro. from aluno import Aluno disponibiliza a classe; não deve abrir uma janela.

O callback lê os textos, chama aluno.atualizar e mostra o resultado. A conferência das notas permanece em aluno.py, evitando duas versões da mesma regra.

Se um import falhar, confira nome do arquivo, pasta dos módulos e interpretador. Não nomeie seus arquivos como tkinter.py ou math.py.

Para conferir o uso da interface, localize o foco atual e percorra os controles com Tab; use Shift+Tab para voltar. Com foco no botão, teste seu acionamento pelo teclado. Observe grupos e rótulos, teclado/expansão, mensagens e identificação dos retratos conservados da A05. Depois de uma recusa, corrija a entrada na mesma sessão e descreva o que permaneceu.
