Entenda a ideia e faça um ensaio ↗

1. Problema concreto

O callback Salvar ficou longo: ele lê campos, converte preço, escolhe incluir ou editar e ainda acessa o banco. Como dividir esse trabalho?

2. Entenda a ideia

A interface cuida de campos, seleção e mensagens. O controller é uma classe que coordena a ação: recebe dados comuns, escolhe a operação e chama o repositório.

O repositório cuida de guardar e consultar dados. Uma versão pode usar memória e outra SQLite. Para o controller trocar uma pela outra, ambas precisam oferecer os mesmos métodos com comportamentos combinados.

Esse combinado é o contrato: nomes dos métodos, argumentos, resultados e falhas esperadas. Não é obrigatório herdar de uma classe base para cumprir o mesmo contrato.

Primeiro extraia uma operação já funcionando. Passe textos e IDs, não Entry ou Treeview. Teste essa operação no terminal antes de modificar todos os botões.

3. Exemplo comentado

Trocar a fonte mantendo o método listar

Regras e detalhes para consultar durante o desafio

GUI → CadastroController → repositório. O controller interpreta o preço e escolhe a operação; o repositório cuida de armazenamento. RepositorioSqlite e RepositorioMemoria oferecem os mesmos métodos; a interface não precisa conhecer os detalhes de cada implementação.

Comece por uma operação já funcionando. Escreva o que Salvar recebe, o que pode devolver e quais falhas comunica. Só depois mova essa coordenação para CadastroController, mantendo as regras e os IDs.

O callback lê widgets e mostra mensagens. O controller recebe valores comuns, sem Entry ou Treeview, e chama o repositório. O callback recebe a falha para orientar a pessoa; não os esconda devolvendo uma lista vazia como se a gravação tivesse funcionado.

Interface de módulo é um contrato de uso: nomes de métodos, argumentos, retornos e erros. Duas classes podem atender ao mesmo contrato sem herdar de uma base comum; o chamador precisa observar o comportamento combinado.

O repositório em memória conserva IDs durante sua sessão e devolve cópias descritivas. A implementação SQLite conserva dados após reabrir. Essa diferença deve ser documentada, sem fingir persistência permanente onde não existe.
